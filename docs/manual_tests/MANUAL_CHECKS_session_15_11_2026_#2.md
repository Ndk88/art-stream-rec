# Ручные проверки после доработок (сессия #2)

Что Claude Code сделать сам не может: смотреть на окно, работать с реальным Madrix/TouchDesigner, открывать Unreal. Это делаете вы. Начинайте, когда Claude Code закончит и закоммитит всё на `dev/v1.2.0`.

**Подготовка.** Обновите ветку (`git pull`), запускайте приложение через `run.bat debug` (с консолью, чтобы ошибки были видны), тестер через `packets_tester.bat`. Свободного места на диске нужно не меньше 2 ГБ.

**Как присылать.** Скриншоты кидайте в чат картинками. Текст окна статистики лучше скриншотом, потому что выделить его может не получиться. Консольный вывод копируйте текстом. Всё, что Claude Code запишет в репозиторий (папка `#2`), я прочитаю из ветки сам, присылать не нужно.

## M1. Окно приложения (проверки из раздела 4 документа issues)

В `run.bat debug` откройте приложение, нажмите **Start Server**. В отдельной консоли запускайте тестер.

| # | Что проверить | Как | Что прислать |
|---|---|---|---|
| 1 | Базовая запись PLSQ | Тестер: `packets_tester.bat 127.0.0.1 6454 104 1 --duration 30`. В рекордере 104 чипа, 30 fps, длительность 6, формат `.plsq`, **Start Record** | Скриншот окна после сохранения. Затем `python tools\validate_plsq.py <файл>` и его вывод |
| 2 | Запись JSON на 1 universe | Тот же тестер, переключатель формата на JSON, запись | Скриншот окна, размер файла |
| 3 | Счётчик universe (I-07) | Не запуская запись, вводите по очереди и читайте поле «Universes (calculated)»: 104 / 128 / 129 / 384 чипа (start channel 1); 256 чипов при start channel 2; 64000 чипов; 100 чипов при start channel 512 | Таблица «ввод → что показано». При 384 и больше кнопка JSON должна стать серой |
| 4 | Формат против расширения (I-06) | Формат `.plsq`, в поле пути вручную напишите `.json` или `.txt`, нажмите Start Record | Скриншот ошибки в блоке статистики |
| 5 | Папки (I-04) | Путь `D:\нет_такой_папки\seq.plsq` и запись: папка должна создаться. Затем путь в папку, куда писать нельзя (например `C:\Windows\System32\x.plsq`) | Скриншот ошибки второго случая. Приложение после этого должно остаться рабочим |
| 6 | Длинные заметки (I-05) | В PowerShell `("a"*70000) \| Set-Clipboard`, вставьте в Developer Notes, Start Record. Потом то же с `("я"*40000)` и с `("я"*30000)` | Скриншоты: первые два случая отказ с размером, третий запись проходит |
| 7 | Сокращённый blend (I-11) | Тестер идёт, длительность 0 (ручная остановка), 30 fps, включите Loop blend 30, нажмите Start Record и остановите вручную примерно через 1,5 с (должно получиться больше 30, но меньше 60 кадров) | Скриншот предупреждения о сокращении blend и `validate_plsq` файла: в `post_loop_blend_frames` должно быть меньше 30 |
| 8 | Большая установка (I-08, I-01) | Тестер: `packets_tester.bat 127.0.0.1 6454 64000 1 --fps 60 --duration 60` (если пишет `behind schedule`, добавьте `--procs 2`). Рекордер: 64000 чипов, 60 fps, длительность 20, Loop blend 30, формат `.plsq`. Во время записи и при остановке смотрите, отзывается ли окно | Скриншот статистики во время записи (сжатый вид на 500 universe), скриншот во время «Finalizing...», вывод `validate_plsq`. Ответьте: окно зависало? на сколько секунд? |
| 9 | Закрытие окна при записи | Запустите запись из п. 8 и закройте окно крестиком посреди записи | Что произошло: файл сохранился и проходит `validate_plsq`? |

Предупреждения про короткие пакеты (I-10) вручную не проверяются: тестер таких пакетов не шлёт, это закрыто автотестами.

## M2. Реальный источник (Madrix 5 или TouchDesigner)

Это главная проверка логики целых кадров: нужно узнать, что источник реально шлёт.

1. В источнике настройте вывод Art-Net на `127.0.0.1:6454` с нужным числом universe (лучше несколько, минимум 3, чтобы JSON был заблокирован).
2. В рекордере выставьте тот же Start Universe (смотрите список «Universes received») и число чипов, поставьте галочку **Wait for complete source frames**. Запишите 10–20 секунд.
3. Повторите запись с выключенной галочкой.
4. Пришлите: скриншот статистики во время приёма (universe, частота, `lost`, `partial`, строка preflight), вывод `validate_plsq.py` для обоих файлов, и ответы на вопросы:
   - в источнике включён ArtSync (синхронизация) или нет?
   - все universe шлются в каждом кадре, или только изменившиеся?
   - какой fps выдаёт источник?

   Если у вас есть Wireshark, можно приложить скриншот фильтра `artnet` на пару секунд трафика: нас интересуют пакеты ArtSync (OpCode 0x5200) и значения Sequence в ArtDMX. Без Wireshark ответов на вопросы выше достаточно.

## M3. Старый Blueprint-парсер JSON (проверка R2, которую никто не делал)

1. Запишите JSON на 1 universe из рекордера (п. 2 из M1).
2. Положите файл туда, откуда его читает ваш актор в режиме Pre Installed, и загрузите как обычно.
3. Пришлите: загрузился ли без ошибок, и скриншот Output Log. Если в логе есть предупреждения про неизвестные ключи или ошибки парсинга, приложите их текстом.

## M4. Сборка exe и запуск `.bat`

1. `pip install pyinstaller`, затем в папке репозитория `pyinstaller --onefile --noconsole main.py`.
2. Запустите `dist\main.exe`, сделайте запись из M1 п. 1.
3. Запустите `run.bat` без `debug` (окно должно появиться без консоли) и `packets_tester.bat` без аргументов.
4. Пришлите: заработал ли exe, и текст ошибки, если нет.
